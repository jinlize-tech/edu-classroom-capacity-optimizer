## 2. 用户、痛点与目标

- 用户：教务主管、校区负责人、运营经理
- 痛点：教室看似排满，但黄金时段忙、非黄金时段空，班容和课程结构未优化，资产利用率被高估。
- 目标：按时间段、教室、课程和教师分析产能与满班率，生成编排情景和释放/扩班建议。

## 3. 输入契约

| 键 | 名称 | 类型 | 必填 |
|---|---|---|---|
| `rooms` | 教室清单 | array | 是 |
| `open_hours` | 每周开放时段 | array | 是 |
| `classes` | 现有班级 | array | 是 |
| `period` | 分析周期 | string | 是 |
| `demand_assumptions` | 需求假设 | array | 否 |
| `capacity_rules` | 容量与使用规则 | string | 是 |

## 4. 工作流

1. 建立时段容量
2. 计算需求与利用率
3. 找瓶颈和空档
4. 模拟调班/合并/加开
5. 检查硬约束
6. 输出行动建议

## 5. 阶段状态

| 阶段 | 动作 | 退出成果 |
|---|---|---|
| S1_SCOPE_CONFIRMATION | 确认目标、校区/岗位/课程范围、期限、交付格式和可用资料。 | 任务确认单与最多3个关键缺口 |
| S2_EVIDENCE_INVENTORY | 盘点教室清单、开放时段、班级与人数、课程时长、教师可用性、周期、容量规则、需求预测，标记来源、版本、敏感字段与冲突。 | 证据清单、缺口表和冲突表 |
| S3_PROFESSIONAL_DIAGNOSIS | 围绕按时间段、教室、课程和教师分析产能与满班率，生成编排情景和释放/扩班建议。进行专业诊断，形成问题树和优先级。 | 问题树、风险和优先级 |
| S4_SOLUTION_DESIGN | 按建立时段容量 → 计算需求与利用率 → 找瓶颈和空档 → 模拟调班/合并/加开 → 检查硬约束 → 输出行动建议设计首选方案和受限备选方案。 | 方案、责任人、完成标准 |
| S5_HUMAN_CONFIRMATION | 由业务负责人复核输入事实、关键假设和最终成果适用范围。 | 确认记录、未决项和升级项 |
| S6_FINAL_DELIVERY | 生成完整交付成果，执行结构、证据、安全、品牌和独立安装检查。 | 最终成果、范围限制和复盘指标 |

## 6. 核心成果

- `产能热区表`
- `满班率`
- `瓶颈`

## 7. 差异化与排重

- 与现有产品：智能排课生成课表；资源调度安排教室；本产品从经营角度评估产能和满班率，不直接改课表。
- 排重检查：部分重叠；使用教室/班级数据，但输出经营优化情景，不是排课冲突处理。
- 独立理由：提供聚合表即可独立评估，不需要排课系统。

## 8. 安全与人工门禁

- 复核角色：业务负责人
- 复核范围：输入事实、关键假设和最终成果适用范围
- 不调用外部收费API。
- 不自动修改外部系统、执行退款、审批合同、处分员工或联系外部人员。
- 高风险产品完成状态必须确认人工复核。
